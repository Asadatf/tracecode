Agent Session Logs — Setup Guide
Hand this file to your coding agent (Claude Code, Codex, Cursor, etc.) and ask it to set up session logging in the current repo. The result: every prompt you type and every final response the agent gives is written to `.claude-logs/` in the repo and committed with the work. Each subagent's brief and the report it sends back are captured too. None of the intermediate tool calls, file reads, command output or work artefacts are recorded.
What this does

* A hook runs a small Python script at three points: when a prompt is submitted, at the end of every turn (`Stop`), and when a subagent finishes (`SubagentStop`).
* The script reads the agent's own session transcript, the JSONL file the agent already writes for itself. It turns that into a clean markdown digest with frontmatter stats.
* Output goes to `<repo>/.claude-logs/<timestamp>_<session-id>.md`, so each repo's sessions land in that repo's own log directory.
* `.claude-logs/` is the one directory for every agent (Claude Code, Codex, Cursor, Aider, etc.): one repo, one log location, one commit policy. Don't pick a per-agent name like `.codex-logs/`. Reviewers and tooling then have one place to look.
* What is kept:
   * User prompts. Context the IDE or the agent harness adds is stripped: the open file, the editor selection, system reminders.
   * The final assistant text before each next prompt.
   * For each subagent: the prompts it was sent (the first brief and any follow-up messages) and the report it handed back. These appear in a "Subagents" section at the end of the session file, oldest first.
* What is dropped: tool calls, tool results, file diffs, thinking blocks, a subagent's intermediate steps, and harness events. Harness events are things like background-task notifications and messages between agents; they are delivered as user turns but nobody typed them.
* Redaction: every line is redacted before it is written. That covers credential-shaped strings (API keys, JWTs, tokens, connection strings, private keys, `SECRET=value` lines) and email addresses other than GitHub noreply addresses.
* One file per session: each run overwrites that session's file, so there is only ever one log per session.
* Attribution: each log records who ran the session in its frontmatter: git author name, git email (local part masked), and GitHub login. So the log itself answers "whose session was this" without inspecting the commit.

The intent is "what did I ask, what did the agent say back, and what did it hand off to subagents". It is a conversation transcript, not an audit log of operations.
