### 2. Recommendation contract & reason codes
`rankRecommendations(evidence, { generatedAt?, evidenceHash? }) → Recommendation`:
```ts
Recommendation {
  v: 1
  generatedAt: string | null        // volatile, excluded from the hash
  evidenceHash: string              // reuses computeEvidenceHash (not duplicated)
  focusConcepts: string[]           // ≤3, sorted
  rankedProblems: {
    slug, score, reasonCode, reasonText,
    evidenceRefs: { problemSlug, metric, value }[]   // every metric resolves in evidence
  }[]
  diagnosis: { source:'fallback', stale:false, summary(≤280), nextStep(≤160),
               claims:{ problemSlug, metric }[] }     // all claims resolvable
}
```
**Reason codes** (stable, cache/analytics-safe): `not_attempted`, `open_repeated_failures`, `in_progress`, `solved_revision`.
`lookupMetric(evidence, slug, metric)` is exported — the single resolver M7.4 will reuse to reject AI claims that cite evidence the engine doesn't have.

### 3. Ranking algorithm & tie-breaking
Score = tier (by learner **state**, not attempt count) + a bounded within-tier nudge:
- `open_repeated_failures` **100** · `in_progress` **80** · `not_attempted` **70** · `solved` **20**
- `STRUCTURAL_FOCUS_BONUS +4`: an *attempted* problem whose latest fingerprint still shows a **recurring nested-loop shape** alongside failures.
- `REVISION_BONUS +4`: a *solved* problem reached only after earlier failures → the better revision target.
- Both bonuses are ≤4, below the 10-point minimum tier gap, so they **never cross a tier**.

Tie-break: **score desc → difficulty (easy<medium<hard) → slug**. Fully deterministic; no clock, no randomness.

### 4. Representative recommendations
- **Cold start** → both easy problems `not_attempted`; "Start with …" accessible pick.
- **Ongoing failures** (fail×3) → that problem leads (`open_repeated_failures`), "focus on the tests still failing".
- **Solved after struggle + an untouched problem** → recommends the **new** problem, summary recognizes "solved … after some earlier unsuccessful attempts" (no mastery claim).
- **All solved** → honest completion + "Revisit two-sum — you first solved it on attempt 3", never a pretend new problem.
- **Contradictory/mixed records** → neutral "records are mixed, no clear pattern yet; run all its tests".

### 5. How AST & M6 evidence affect ranking
- **M6** supplies the state (`progress`, `failurePattern.pattern`, `attemptsToFirstSolve`, outcomes) that selects the tier and reason.
- **AST** (M7.2 `sequence.patterns`) adds the `+4` structural nudge and a factual nested-loop note, and feeds `focusConcepts`. Because features flow through `evidenceHash`, a backfill genuinely changes the recommendation (test 7 asserts score 104 vs 100 and differing hashes). Structure is only ever stated as an observed shape — never "O(n²)", "slow", or "wrong".

### 7. Known limitations
- With only two easy problems, cross-problem structural steering (#3) is intentionally minimal — it shows mainly in wording/focus and the within-tier nudge; it scales as the catalog grows.
- Cold-start tie between two equally-easy problems resolves by slug (`contains-duplicate` first) — deterministic but arbitrary absent an "intro order" field.

### 4. AI refresh and concurrency protections
