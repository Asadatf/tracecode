## How selection works (`selection@1`, AC7)
- **Candidates:** every problem not retired. How often and how recently each was used comes from the stored exam history, so there's no separate counter to drift out of sync.
- **Cooldown:** a 7-day cooldown is preferred. If too few problems qualify, it relaxes one day at a time, and with two or more problems it never goes below 1, so yesterday's problem never repeats. With exactly one problem, it's reused rather than cancelling.
- **Weight:** `(1 + min(daysSince, 30)) / (1 + 3 × priorUses)`, so a never-used problem weighs 31. Weights are converted to whole numbers, and the server draws with `crypto.randomInt`.
- **Stored once:** the problem is saved in the same database write that opens the exam, along with a record of the draw. Retries, simultaneous opening requests and later pool changes can never change it, and past exams keep their problem.

## Two side effects of reuse, now handled
- **Repeats are labelled** (AC50). From opening, a repeat says "This problem has appeared in a previous exam and is available in Practice", and its leaderboard is marked "Repeat problem". Nothing calls a repeat unseen, and nothing before opening reveals today's problem or whether it's a repeat.
- **Practice is locked for the exam's problem while it's being examined** (AC49). From 15:00 until that exam's credit is written, the problem's Practice page, Tracy, hints and solution history are unavailable, checked on the server. Without this, participants could look up a repeat during the exam. The lock never starts before opening, so it can't give away the problem. The limit: a Practice page already open before 15:00 can still run code in the browser, which the rules disclose.
