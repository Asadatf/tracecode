# M7 — Personalized Learning Recommendations: architecture proposal

## Component boundaries (M7.1–M7.5)

**M7.1 — Code evidence (AST features, client-side).** Extend the Pyodide worker to also run `ast.parse()` on the submitted source and walk it into a small, bounded structural summary. **Parse, not exec** — no execution on server or client. Persisted with the attempt.

**M7.2 — Evidence assembler (server, pure).** Combines M7.1 code features (latest attempt per problem) with M6 `statistics`/`behavior`/`insights` into one `RecommendationEvidence` object. No I/O beyond reading what M6 already reads; no AI.

**M7.3 — Deterministic recommendation engine (server, pure).** Ranks the catalog problems and picks focus concepts from the evidence. **Always produces a complete recommendation** with no AI involved. This is the source of truth and the fallback.

**M7.4 — AI diagnosis (server, OpenRouter, optional).** Takes M7.3's structured output + evidence, asks OpenRouter for a short natural-language *diagnosis + next step*, validates it with Zod, and attaches it. On any failure → drop it and keep M7.3's templated copy. Called **only** on explicit generate/refresh or the daily cron — never on submit, replay, or page load.

**M7.5 — Delivery (dashboard + email).** Dashboard (a card on the existing `/progress` page) reads the **cached** recommendation. A Vercel cron route generates/refreshes for opted-in learners and sends via Resend, honoring opt-in + dedup.

```
SUBMIT (browser)
  Pyodide worker: run tests  ──(+ ast.parse → codeFeatures)──▶ saveAttempt
                                                               └─ attempts(+codeFeatures)   [no AI]

GENERATE/REFRESH (dashboard-if-stale | explicit | cron)         [server only]
  getLearningAnalytics() ─┐
  latest codeFeatures  ───┼─▶ M7.2 Evidence ─▶ M7.3 rank (deterministic, always)
                          │                      │
                          │           evidenceHash changed & AI on?
                          │                      └─▶ M7.4 OpenRouter → Zod-validate → attach
                          └────────────────────────────────▶ upsert Recommendation (cache)

READ
  dashboard  ──reads──▶ Recommendation (cache)
  daily cron ──reads──▶ Recommendation ──▶ Resend email (opt-in + dedup)
```

## AST approach (compatible with existing Pyodide)

- Add one **additive** worker message `ast` (new `WorkerRequest`/`WorkerResponse` variant), handled right after a successful `run`, reusing the already-booted Pyodide worker. It calls `ast.parse(source)` and a small `ast.NodeVisitor` to count structures. The client passes the result into `saveAttempt`.
- **Why a separate message, not folding into `RunResult`:** `RunResult`/`TraceResult` live in the governed trace contract ([02-trace-contract.md](specs/02-trace-contract.md)) — those shapes "change only with both track owners' agreement." A separate `ast` call keeps the trace contract untouched. (Alternative: an optional `codeFeatures` field on `RunResult` saves a round-trip but needs that agreement — flagging for your call.)
- `ast.parse` builds a syntax tree **without running the code**, so this satisfies "no server execution" and adds no security surface beyond what the run already does.
- The server/cron **cannot** run Pyodide, which is exactly why features are computed in the browser and persisted — the cron path reads them back, never re-parses.

## Minimal contracts

```ts
// M7.1 — bounded, structural, numbers/enums only (no raw identifiers → no PII)
type CodeFeatures = {
  loops: { for: number; while: number; maxDepth: number }
  branches: number
  returns: number
  defs: number
  recursion: boolean
  usesDict: boolean; usesSet: boolean; usesSorted: boolean
  calls: string[]        // builtin names only, capped
  lineCount: number
}

// M7.2 — everything the engine and the AI diagnosis get to see
type RecommendationEvidence = {
  perProblem: { slug: string; mastery: 'solved'|'attempted'|'none';
    trend: ImprovementTrend; failurePattern: FailurePattern;
    persistentTestFailures: string[]; code?: CodeFeatures }[]
  concepts: Record<string, { attempted: number; solved: number }> // by conceptTag
  topInsights: { type: InsightType; problemSlug: string|null }[]   // reuse M6 types
}

// M7.3 output + M7.4 enrichment (one cached object, reused by dashboard + email)
type Recommendation = {
  generatedAt: string
  evidenceHash: string                 // skip regen/AI when unchanged
  focusConcepts: string[]
  rankedProblems: { slug: string; score: number; reasonCode: string }[]
  diagnosis: { source: 'ai' | 'fallback'; summary: string; nextStep: string }
}
```

## Persistence that's genuinely necessary (3 things)

1. **Code features per attempt** — because the cron/email path has no browser. Minimal: a nullable `codeFeatures Json?` column on `Attempt` (written by an extended `saveAttempt`), or a sibling `AttemptCodeFeatures` table if you'd rather not touch `Attempt`. *No change to M6's loader.*
2. **Recommendation cache** — one current row per user (`userId` PK): the M7.3 output + validated diagnosis + `evidenceHash` + model + `createdAt`. This is what makes "OpenRouter only on generate/refresh" and "reuse for dashboard + email" both true.
3. **Email prefs + dedup marker** — `reminderOptIn: boolean` and `lastReminderSentAt` (own row or folded onto a user-prefs row). Dedup rule: skip if sent within ~20h **or** no new activity since last email.

Everything else (statistics/behavior/insights) stays **derived on the fly** — no new persistence. All new user-scoped tables get **RLS enabled, no policy** (hand-written migration, enforced by `pnpm check:rls`) per [database/auth rules](docs/rules/database.md).

## Security / privacy / cost / failure

- **Security:** AST is `ast.parse` only (never `exec`), in the existing sandboxed worker; server runs no Python. OpenRouter is server-only through the lint-enforced `src/server/ai/openrouter.ts` wrapper + `trackAiCall`. Cron route guarded by `isCronAuthorized`. Recommendations scoped by session `userId`, never from the request body.
- **Privacy:** the AI prompt gets the **compact structural evidence + M6 numbers/enums, never the raw source or any PII**. `ai_usage.meta` carries ids/enums only (`feature: 'learning_recommendation'`). Email goes to the learner's own address, opt-in, with unsubscribe.
- **Cost:** AI fires only on explicit refresh + the per-user daily cron, and only when `evidenceHash` changed; cheap model mapped in `OPENROUTER_SLUGS`; bounded `max_tokens`; every call costed in `ai_usage`. Dedup prevents duplicate sends/regens.
- **Failure handling:** M7.3 always returns a full recommendation; AI is strictly additive. OpenRouter error/timeout/invalid-JSON (Zod fails) → `source: 'fallback'`, templated copy, `captureError`, dashboard and email unaffected. Mirror M6's degradation contract (`authenticated` / `available`); never throw into the caller.
