## Did streaming need a protocol change? Yes
The Python runner already ran tests one at a time in a loop. But the whole loop was a single synchronous call, and the worker posted one `run_result` at the end. No per-test events existed, so I made the smallest additive extension:
- **Runner:** after each test, `RUN_PROGRAM` calls an optional `REPORT_TEST` function. It does this after the result is recorded, so grading and any failure to report are unaffected.
- **Worker:** it turns that call into a `test_result` message, posted synchronously before the next test starts.
- **Engine:** `runCode(request, { onTestResult })` forwards events only in strict order for the current call. It ignores duplicates, gaps and malformed events. A faulty listener can't break the result.

`run_result` is unchanged and remains the only graded, saved result.
